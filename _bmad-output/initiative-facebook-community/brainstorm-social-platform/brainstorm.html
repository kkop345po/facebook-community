02 / CONVERGE

先完成交流，再讓社群長大。

以下為教練整理的 MoSCoW 建議，屬於規劃方向，並非使用者已確認的最終選擇。品牌暫稱「串連」、桌面三欄與手機單欄也都仍是視覺提案。

MUST / 核心循環

第一版要能真正使用

註冊、信箱驗證與重寄、登入登出、忘記密碼、個人資料、文字貼文增改刪、時間排序動態牆、留言、按讚、分頁，以及權限與限流。

直播、廣告、Marketplace、複雜推薦、即時私訊。

03 / THE FIRST CONVERSATION

從一封信，走到一句回應。

  1. 01A 建立帳號Email 與密碼註冊。
  2. 02A 驗證信箱清楚等待狀態，必要時重寄。
  3. 03A 登入與發文完成個人資料，發出第一則文字。
  4. 04B 完成獨立驗證使用另一個真實帳號登入。
  5. 05B 留言與按讚A 能看見互動的結果。
  6. 06重新整理仍保留真實貼文與回應由資料庫保存。
04 / CONDITIONS, NOT PROMISES

公開網址，是起點而非全部。

前端與公開入口

React 建議由 Cloudflare Workers Static Assets 提供；開發階段以 workers.dev 作公開網址。同源 /api 代理可簡化 Cookie。隨機 trycloudflare.com Tunnel 僅用於短期展示。

Flask 執行環境待驗證

優先做 Python Workers 套件相容性驗證。官方已有 Flask 文件，但 PostgreSQL 驅動仍需實證；若傳統 Python 驅動不相容，建議採 Cloudflare Containers，需付費方案。

資料庫與連線

PostgreSQL 採外部託管；開發可使用本地 PostgreSQL。容器經 TLS 直連；不預設 Hyperdrive 能使用 Python 資料庫驅動。遷移、索引、備份與還原演練都在想法庫中。

Resend 與寄件網域

對一般使用者寄信，需要自有且已驗證的寄件網域。網站網域與發信網域分開配置，不能將 workers.dev 當作寄件網域；服務金鑰與登入資料留在後端。

尚未解決的條件：Flask／PostgreSQL 驅動的實際相容性、自有寄件網域與正式發信配置、託管資料庫與最終後端環境，都需在實作部署時確認。此紀念頁不代表網站已開發、已寄出驗證信或已上線。

05 / PROOF OF CONNECTION

兩個帳號，才能證明一段對話。

以下是待執行的驗收標準，目前沒有測試通過或部署完成的宣稱。

  1. 兩個獨立帳號完成實際信箱驗證與互動。
  2. 過期權杖與重複使用權杖受到正確處理。
  3. 未驗證帳號不能寫入內容。
  4. 非作者不能修改或刪除他人的貼文。
  5. 登出後的登入狀態失效。
  6. 分頁載入舊貼文不重複。
  7. 重新整理仍保留真實貼文、留言與互動。
  8. 手機可以完成註冊、登入與互動操作。
THE CONNECTION THAT MATTERS

一個社群的最小單位，
是被另一個人接住的話。

身分驗證是門，貼文是邀請，留言與按讚是回應，資料保存則讓回應留下。這些原本分散在不同技巧的想法，連成同一個產品核心：可相信、可完成、可再次看見的互動。

接下來的價值，在於把建議範圍與部署限制轉成可執行需求，再以兩個真實帳號驗證完整循環。
