# 發想來源提取：Facebook 類型社群網站

來源：`../brainstorm-social-platform/.memlog.md`（全文讀取）。此文件僅整理來源證據，不是 PRD，亦不代表使用者已接受教練提案。

## 用戶明確需求（由來源轉述）

- 建立 Facebook 類型社群網站，供真實用戶註冊、登入與互動。
- 指定 React 前端、Flask 後端、PostgreSQL 資料庫。
- 需要 Cloudflare 提供的公開／臨時網址，以及透過 Resend 寄送驗證信。
- 選擇「Ideate for me」發想模式；專案主題為 `facebook-community`。
- 證據界線：來源所有逐條記錄皆標記 `by coach`；上述要求是教練對使用者指定內容的轉述，來源未附使用者逐字原文。

## 教練建議，尚未獲用戶確認

- 核心互動循環：註冊 → 信箱驗證 → 登入 → 發文 → 另一帳號留言／按讚 → 重新整理仍保留。
- 教練提出 MoSCoW 排序；其中「decision by coach」不等於使用者已同意範圍。
- 好友、圖片／頭像、通知屬 Should／建議第二期候選，並非使用者同意延後或排除。檢舉亦列 Should。
- 繁體中文、桌面三欄／手機單欄、獨立品牌暫稱「串連」均為視覺提案。
- 十人封閉測試、校園／社區情境只是發想例子；目標受眾與初始測試人數未由用戶確認。

## 重要限制與待驗證依賴

- 必須保留 React、Flask、PostgreSQL、Cloudflare 網址與 Resend 驗證要求；具體部署方案仍待決定。
- 教練建議 React 使用 Workers Static Assets／workers.dev；Flask Python Workers 須先驗證套件與 PostgreSQL 驅動相容性，不能視為已證實可行。
- 備案為 Cloudflare Containers（來源指出需付費方案）搭配外部託管 PostgreSQL、TLS 直連；不預設 Python 驅動可使用 Hyperdrive。本地 PostgreSQL 可供開發。
- 隨機 trycloudflare.com Tunnel 在來源中僅建議短期展示；不能把該方案等同穩定正式部署。
- 來源指出 Resend 向一般用戶發信需要自有、已驗證寄件網域，workers.dev 不能充當寄件網域；網站網址與發信網域須分別配置。此為來源所述依賴，尚待實作階段重新驗證。
- 登入資料、服務金鑰留在後端；安全雜湊、伺服器權限檢查、CSRF／XSS／SQL 注入防護、安全 Cookie、權杖單次使用與限流皆為教練候選要求。
- 來源階段僅完成發想規劃，尚未實作、部署或實際發信；不得聲稱已上線或通過驗收。

## MVP 候選（教練 Must，待範圍確認）

- Email／密碼註冊、信箱驗證、重寄與冷卻、過期流程、避免重複帳號。
- 登入／登出、忘記密碼與重設流程、可撤銷工作階段。
- 基本個人資料、純文字貼文新增／編輯／刪除、依時間排序的動態牆。
- 留言、單一按讚／取消、游標分頁。
- 寫入前驗證、作者修改權限、認證與註冊限流及必要安全處理。
- 可靠寄信、資料持久化與必要的狀態／錯誤回饋；詳細實作策略仍是提案。

## 驗收候選（教練提出，尚未執行）

- 兩個獨立帳號完成真實註冊、收信驗證、登入、發文及彼此留言／按讚。
- 過期與重複權杖受到正確處理；未驗證帳號不能寫入。
- 非作者無法改刪貼文；登出後原工作階段失效。
- 動態牆分頁無重複，重新整理仍保留真實資料。
- 手機可完成主要操作；錯誤、待驗證、寄信失敗與重試狀態清楚。
- 應分開記錄本地測試、實際寄信及公開部署的證據。

## 非目標候選與後續範圍

- 教練建議本輪不做：直播、廣告、Marketplace、複雜推薦、即時私訊；尚非用戶確認的排除項。
- Could 候選：社團、活動、收藏；其他發想包含封鎖、資料匯出、停用帳號、主題追蹤與摘要通知，均不應自動納入 MVP。
- 尚未確認：目標受眾、品牌、可接受費用、正式部署方式，以及各候選功能的最終取捨。
